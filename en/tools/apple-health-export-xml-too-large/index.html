Why Apple Health export.xml Crashes Excel & Browsers

1. 1,048,576-Row Excel Cap

An Apple Watch easily produces 2–10 million individual heart rate, step, and calorie XML tags over a few years—blowing past Excel’s hard row ceiling immediately.

2. RAM Explosion in DOM Parsers

Opening a 1GB XML file in Chrome, VS Code, or naive web tools builds a ~10GB DOM tree in memory and kills the tab. Streaming 4MB slices keeps memory flat.

3. Duplicate Watch + iPhone Rows

Even if you manage to split raw XML manually, raw rows double-count steps across iPhone and Apple Watch and split sleep across midnight. HealthDock cleans both automatically.

Large Export Troubleshooting FAQ

My iPhone gets stuck on “Exporting Health Data…” — any tips?

Keep the Health app open on screen and disable Auto-Lock temporarily (Settings → Display & Brightness → Auto-Lock → Never) while exporting multi-year history. Once the share sheet appears, AirDrop export.zip directly to your Mac rather than emailing it.

What if my browser doesn’t support streaming ZIP decompression?

Modern Chrome, Safari (16.4+), Edge, and Firefox all support native DecompressionStream. If you’re on an older browser, simply double-click export.zip in Finder and drop the inner export.xml file here.
